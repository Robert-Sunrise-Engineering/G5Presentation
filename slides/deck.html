The question — where should the LLM sit?06 / 07

Good at language. Bad at math. So place it.

Zone 1 · outside Read the documents state schema, data dictionaries, policy PDFs → gap reports, checklists no data touched
Zone 2 · input edge Draft the checks English → candidate Arcade / SQL; text & address QC; human reviews and owns it code is reviewed first
THE MIDDLE Data + deterministic checks geometry, area math, topology, duplicates, thresholds — proven, reproducible NEVER
Zone 4 · output edge Explain the findings triage memos from verified findings; per-finding notes for reviewers advisory only — facts above the prose
Zone 5 · always Humans decide accept, reject, route to the recorder — sign-off is a person’s every time
Zone 1, 2 and 4 are work, not worship. The middle never moves — same shape as Utah County’s CV model: AI drafts the queue, the check proves it, a human decides.
Beat 1 · a check the LLM must never do07 / 07

The LLM can name this trap. It must never do the math.

Parcel area, Kanarraville demo subset (508 rows), indexed to the equal-area projection:

EPSG:5070 ALBERS · EQUAL-AREA
100
EPSG:3857 WEB MERCATOR · NATIVE CRS
159.3

Every acreage compared in the native CRS is +59.3% off the map. Web Mercator is conformal — it keeps angles, not area — and the distortion grows with latitude. 37.6° N is exactly where it bites. Stated-assessment acres are measured against the wrong Earth.

The LLM may

know the trap and put it on your checklist — “your native-CRS areas are not defensible; verify in an equal-area projection.” Knowledge like this is free.

It must never

run the arithmetic, reproject, or “fix” an acreage. The LLM flags the possibility; deterministic code in ArcGIS proves the fact.
